# 샘플 데이터·모킹 사용 범위

확인 기준: 2026-11-15, 현재 체크아웃의 FE 코드와 연결된 AI 코어 사용 지점. 설치된 APK 버전이나 휴대폰에 남은 사용자 저장 데이터까지 조사한 결과는 아니다.

## 제출용 설명

일반 앱은 수집한 실제 행사·공모전 데이터, 사용자 일정, 외부 경로·날씨 API를 사용한다. 가상 행사·일정은 데모 및 자동 테스트를 위해 코드에 남아 있으나, 기본 진입점 `lib/main.dart`에서는 자동 주입하지 않는다. 경로 화면의 ‘데모: 서울역 → 부산역’ 버튼은 남아 있으며, 출발지·도착지·날짜만 미리 채운다. 경로 검색 결과는 실제 API에서 조회한다.

자동 테스트에서는 외부 HTTP 응답, AI 응답, 캘린더, 저장소, 현재 시각, 알림 발송기를 필요에 따라 대체한다. 실기기 알림 진단은 가상 파업·통제 입력과 격리된 저장소를 사용하되 실제 Android 알림 플러그인으로 발송했다. 따라서 모킹 테스트 통과와 실제 공급원 연동, 실제 알림 수신 검증은 각각 구분한다. 앱 종료 상태의 서버 푸시(FCM)는 구현되지 않았다.

## 실행 환경별 범위

| 구분 | 사용하는 샘플·모킹 | 사용자에게 미치는 범위 | 코드 근거 |
| --- | --- | --- | --- |
| 일반 앱 시작 | 샘플 행사·기본 일정 자동 주입 없음 | `main()`이 `liveEventsEnabledProvider=true`로 설정. 실제 피드와 사용자 저장 일정을 사용 | `lib/main.dart`, `lib/data/providers.dart`의 `eventsProvider`, `PlansController.build()` |
| 데모/테스트용 Provider 설정 | `sampleEventsAt(now)`, `samplePlansAt(now)` | 위 Provider가 false일 때 가상 행사·일정 활성화. 기준 날짜를 옮겨 재현하며 샘플 배지 표시 코드가 남아 있음 | `lib/data/providers.dart`, 코어 `package:liferadar_core/demo.dart` |
| 경로 화면 데모 버튼 | 서울역·부산역 좌표, 2026-11-20 날짜 | 버튼을 눌러야 입력됨. 누르는 즉시 모의 경로를 생성하지 않으며, 이후 검색은 Google Routes/Kakao Mobility 호출 | `lib/features/route/route_panel.dart`, `route_controller.dart`의 `useDemo()`, `search()` |
| 자동 테스트 | 고정 행사·공고·일정·파업·통제, HTTP/AI 응답, 캘린더 대역, 메모리 저장소, 고정 시각, 알림 발송 대역 | 테스트별로 필요한 부분을 대체. 실제 계정·외부 서비스·휴대폰 수신 검증을 대신하지 않음 | `test/app_test.dart`의 `pumpApp()`, `test/assistant_test.dart`, `calendar_add_test.dart`, `live_*_test.dart`, `travel_impact_test.dart` 등 |
| 실기기 알림 진단 | 고정 파업·통제·일정·시각, 메모리 저장소, 날씨 API 대역 | 별도 진입점으로 실행. 실제 알림 플러그인에 `[검증용]` 알림 등록. 기본 `main()`에서는 실행하지 않음 | `tool/verify_traffic_notifications_device.dart`, [기기 검증 기록](verification/traffic-notifications-20261113.md) |

`liveEventsEnabledProvider`의 선언 기본값은 false다. 일반 앱은 `main()`의 override로 true가 되지만, `LifeRadarApp`을 직접 띄우는 위젯 테스트는 이를 거치지 않아 샘플을 사용할 수 있다. 이 값을 운영 화면의 사용자 설정으로 전환하는 기능은 없다.

## 샘플로 분류하지 않는 데이터와 대체 동작

| 항목 | 실제 처리 | 해석 시 주의점 |
| --- | --- | --- |
| `assets/data/events.json`, `contests.json` | 수집한 실제 공개 정보의 번들 스냅샷 | 실시간 조회 결과는 아니다. 파일의 생성·검증 시각 기준이며, 공모전에는 수동 공개 페이지 확인 기록도 포함된다 |
| 피드·날씨·AI 캐시 | 과거에 받은 데이터를 재사용 | 캐시를 사용했다고 가상 데이터가 되는 것은 아니지만 최신성은 별도로 봐야 함 |
| 행사 피드 로딩 실패 | 번들·캐시 사용 또는 빈 피드 | 일반 앱에서 네트워크/에셋 실패를 이유로 샘플 행사·일정을 자동 삽입하지 않음. `LiveEvents.initial()`, `EventFeed.load()` 참고 |
| Gemini 호출 실패·키 미설정·검증 실패 | 카드의 규칙 문장 유지, 비서의 후보 기반 조건 검색 응답 | 모의 Gemini 성공 응답을 반환하는 것이 아님. 이 응답을 실제 AI 호출 성공으로 집계하면 안 됨 |
| 행사 이미지 없음·다운로드 실패 | 코드로 그린 기본 커버 | 가상의 행사 레코드나 실제 행사 포스터를 만드는 기능이 아님 |
| 경로의 추가 거리·시간 | 실제 경로와 계산 로직으로 산출. 대중교통 추가 시간에는 왕복 이동 추정이 포함됨 | 추정값과 외부 API의 실측/조회값을 구분해야 함 |

## 알림과 샘플 차단

- 일반 실행에서는 `SignalNotifier.dispatch()`가 `source == 'sample'`인 일정이나 샘플 행사에 연결된 알림을 제외한다. `lib/data/notifications.dart` 참고.
- 교통 영향 갱신 대상에서도 샘플 일정을 제외한다. `lib/data/travel_impact.dart` 참고.
- 샘플 배지·편집 안내는 코드에 남아 있다. 샘플 일정을 사용자가 저장하면 `saveLocal()`이 `source='local'`로 바꿔 사용자 일정으로 저장한다. 샘플 기능의 비활성화가 과거에 저장한 사용자 데이터 삭제를 의미하지는 않는다.
- 자동 테스트에서 알림 발송 대역이 호출된 것은 실제 시스템 알림 수신 증거가 아니다.
- 기존 실기기 기록은 가상 입력으로 Android 활성 알림 2건 등록을 확인한 결과다. 실제 발생한 파업의 자동 감지, 배너 표시 촬영, 앱 종료 상태 수신까지 검증한 결과는 아니다.
- 주간 공모전 백그라운드 작업은 수집 작업이며 알림 발송 작업이 아니다. 새 교통 정보 확인은 앱 실행·복귀 및 실행 중 5분 주기에 연결돼 있다.

## 확인 범위와 남은 제약

이 문서는 코드 경로와 기존 검증 기록을 대조해 작성했다. 이번 문서 작성 과정에서 API를 새로 호출하거나 테스트를 재실행하지 않았다. 테스트 fixture, 도구의 가상 입력, README의 시연 시나리오를 운영 데이터의 실제 발생 증거로 사용하지 않는다. 이전 APK·계정별 캐시에 샘플을 저장해 둔 상태인지 확인하려면 해당 기기의 설치 버전과 저장 데이터를 별도로 점검해야 한다.

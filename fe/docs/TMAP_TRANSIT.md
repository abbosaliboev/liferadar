# 현재 정책: 시간표 조회 복원 (1.0.10+4027)

지도 좌표가 있다는 이유로 시간표가 없는 카카오 대안을 추천한 4026의 동작은 철회했다.
사용자의 “실제로 탈 수 있는 경로로 하되, 안 되면 원래대로” 요청에 따라, 운행 확정·잔여 좌석을 확인할 수 없는 대안 추천은 중단하고 일정 간 경로 선택을 기존 Google Routes 날짜·시간표 조회로 복원한다.

- `MappedTransitOptions.search`는 `googleTransitJourneys`를 직접 호출한다.
- 선택 출발시각 이후 탑승, 구간 출발·도착 시간, 환승 도보시간, 다음 일정 시작 전 최종 도착을 검사한다.
- 초기 대기·환승·마지막 도보를 포함한 실제 시간표상 도착시각과 선택 출발시각의 차이를 총 시간으로 쓴다.
- 상세 지도 좌표 유무는 노선 추천 조건이 아니다. 누락 구간은 임의 보간하지 않는다.
- 시간표 없는 기존 카카오/TMAP 저장 경로는 다시 검색하기 전까지 추천·저장하지 않는다. 기존 데이터 자체는 삭제하지 않는다.
- API 시간표는 예매처의 운행 확정이나 잔여 좌석 조회가 아니다. 확인했다고 표시하지 않는다.

실제 서울시립과학관→청주대학교, 2026-11-27 12:00(KST) 조회에서 시간표 포함 결과 6개를 받았다. 동서울 13:10→청주여객북부정류소 15:10 등의 구간별 시각을 확인했다. 키가 없는 검증 응답은 `test/fixtures/google_scheduled_seoul_cheongju.json`에 보관한다.

아래는 이전 버전의 구현·검증 기록이며, 4026의 추천 정책은 현재 사용하지 않는다.

# TMAP 대중교통 연동 (1.0.8+4025)

기존 카카오맵 표시를 유지하고 대중교통 조회는 TMAP을 우선 사용한다.
로컬 `env.json`의 `TMAP_APP_KEY`를 `--dart-define-from-file=env.json`으로 전달한다.

## 조회와 표시

- `POST https://apis.openapi.sk.com/transit/routes`, 최대 3개 경로를 요청한다.
- 사용자가 고른 출발시각을 한국시각 `searchDttm`으로 전달한다.
- `BUS`, `EXPRESSBUS`, `SUBWAY`, `TRAIN`을 버스·지하철·기차로 구분한다.
- `passShape.linestring`은 `경도,위도` 쌍을 공백으로 나눈 좌표열이다.
  상세 좌표가 있는 시외버스도 다른 버스와 동일하게 지도에 그린다.
- `service: 0`인 구간도 노선 후보에는 남기되 선택한 시각의 운행 여부를 확인하라는 경고를 표시한다.
- 공급자와 공급자 노선 ID를 저장하며, TMAP ID를 검증된 교통 알림 시설 ID로 임의 승격하지 않는다.
- TMAP의 구간 소요시간을 실제 출발·도착 시간표로 만들지 않는다.

## 조회 실패

키가 없으면 기존 Google Routes를 사용한다. TMAP 조회 실패도 Google로 대체한다.
쿼터 초과를 확인하면 1분 동안 반복 TMAP 요청을 피하고 Google 결과에 대체 조회 안내를 표시한다.
시간표·노선·좌표의 공급자를 Google과 TMAP 사이에서 섞지 않는다.
기존 Google 저장 경로의 상세 좌표 갱신도 Google에서만 수행한다.
기존 저장 경로를 TMAP으로 바꾸려면 **경로 찾기**를 다시 실행한 뒤 선택·저장한다.

## 실제 응답 확인 (2026-11-15)

제공된 키로 HTTP 200 정상 응답을 확인했다. 실제 장소 검색 좌표로
서울시립과학관→청주대학교, 2026-11-27 12:00 검색 결과 3개를 조회했다.

- 지선 1224: 상세 좌표 13개
- 수도권 7호선: 경로에 따라 상세 좌표 252개 또는 42개
- 동서울/센트럴시티→청주대 시외·고속버스: 상세 좌표 대신 두 끝점만 제공

따라서 쿼터가 정상이어도 이 시외버스 구간의 실제 도로 노선은 현재 응답으로 그릴 수 없다.
이 경우 승하차 위치만 표시한다. 자동차 경로나 임의의 직선을 실제 버스 노선처럼 그리지 않는다.
원본 응답 기록은 로컬 `.test-tmp/tmap-live-response.json`에 있으며 키는 포함하지 않는다.

정상 TMAP 우선 조회, KST 출발시각, 상세 시외버스 좌표 표시 조건, 쿼터 초과와 재시도 제한,
일반 오류 대체 조회, 운행 여부, 잘못된 좌표를 자동 테스트했다.
전체 테스트와 실제 응답 파싱 검증 139개 및 정적 분석을 통과했다.

## 상세 노선이 있는 경로만 선택 (1.0.9+4026)

사용자 요청에 따라 일정 간 경로 선택은 모든 탑승 구간에 상세 좌표가 있는 경로만 노출한다.
`MappedTransitOptions`가 TMAP/Google 조회와 카카오 대중교통 조회를 함께 실행한다.
좌표가 없는 고속버스·KTX 구간은 자동차/철도망 참고 경로나 직선으로 보간하지 않는다.
카카오 대안은 다른 전체 여정이며, 기존 TMAP 노선에 좌표만 붙이지 않는다.
선택한 대안의 정류장·노선명·예상 소요시간·공급자를 함께 저장한다.

카카오 공식 `GET https://dapi.kakao.com/v2/routing/publictraffic` 응답의
`routes[].steps[].path.points`를 `[경도, 위도]` 순으로 읽는다.
이 API에는 출발 날짜·시각 파라미터가 없어 현재 노선 기준의 예상 경로임을 화면에 표시한다.
미래 날짜의 실제 시간표나 운행 여부가 보장된다고 표시하지 않는다.

실제 서울시립과학관→청주대학교 전체 조회는 HTTP 200, 9개 여정을 반환했다.
첫 여정에 포함된 공도시외버스→청주시외버스터미널 시외 8308은 471개 좌표를 반환했다.
기존 센트럴시티→청주대 고속버스 대신 이 노선을 선택한다면 소요시간과 환승도 함께 달라진다.
모든 구간이 상세한 후보를 소요시간순으로 정렬한 뒤 서로 다른 노선을 우선해 최대 3개 표시한다.
상세 후보가 없으면 선택지를 만들지 않고 안내한다.

검증용 실제 응답은 키를 제외한 `test/fixtures/kakao_seoul_cheongju.json`에 보관한다.
실제 노선 파싱, 좌표 저장·복원, 불완전 고속버스 제외, 공급자 혼합 방지, 전체 미제공,
잘못된 좌표 및 알 수 없는 이동수단 거부, 공급자 오류 시 대안 조회를 테스트한다.

공식 문서: https://developers.kakao.com/docs/ko/kakaomap/rest-api#publictraffic
